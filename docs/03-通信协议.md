# 03 通信协议规范（CHTP/1）

协议名：**CHTP**（Chat Terminal Protocol），版本 1。TCP 承载，全双工，二进制，**大端序**。

## 1. 帧结构（固定 24 字节头）

```
 偏移  长度  字段          说明
 0     4     magic         ASCII "CHT1"
 4     2     version       协议版本 = 1
 6     2     type          消息类型，见 §3
 8     4     flags         位标志，见 §2
 12    8     seq           客户端请求序号；响应回填；服务端主动推送为 0
 20    4     payload_len   负载字节数（不含头），上限 1 MiB
 24    N     payload       TLV 字段序列，见 §4
 24+N  0/4   crc32         仅当 flags.bit0=1 时存在，覆盖 [0, 24+payload_len)
```

约束（服务端必须校验，违反即断连）：

- `magic != "CHT1"` → 断开，日志记 `bad_magic`。
- `version != 1` → 回 `ERROR(BAD_VERSION)` 后断开。
- `payload_len > 1 MiB` → 回 `ERROR(PAYLOAD_TOO_LARGE)` 后断开。
- CRC 校验失败 → 回 `ERROR(BAD_FRAME)` 后断开。

> 采用固定头 + 显式长度的原因：解析不需要扫描分隔符，O(1) 得知整帧边界；
> 长度上限前置校验可以抵御"声明 4GB 长度"的内存攻击。

## 2. flags 位定义

| 位 | 名称 | 含义 |
| --- | --- | --- |
| 0 | `CRC` | 帧尾带 crc32 |
| 1 | `COMPRESSED` | 保留，M6 可能启用 zlib（当前必须为 0） |
| 2 | `PUSH` | 服务端主动推送（客户端可据此区分响应/推送） |
| 3–31 | 保留 | 必须为 0，接收方忽略 |

## 3. 消息类型字典

| 值 | 名称 | 方向 | 说明 |
| --- | --- | --- | --- |
| 0x0001 | `HELLO` | C→S | 握手，声明协议版本与客户端名 |
| 0x0002 | `HELLO_ACK` | S→C | 握手成功，返回服务端版本/时间 |
| 0x0010 | `LOGIN` | C→S | 用户名 + 口令摘要 |
| 0x0011 | `LOGIN_ACK` | S→C | 登录结果，成功带 `user_id` |
| 0x0012 | `REGISTER` | C→S | 注册新账号 |
| 0x0013 | `REGISTER_ACK` | S→C | 注册结果 |
| 0x0020 | `JOIN` | C→S | 加入房间（不存在则自动创建，需 allow_create） |
| 0x0021 | `JOIN_ACK` | S→C | 加入成功，带房间最近 N 条消息 |
| 0x0022 | `LEAVE` | C→S | 离开房间 |
| 0x0023 | `ROOM_LIST_REQ` | C→S | 请求房间列表 |
| 0x0024 | `ROOM_LIST_ACK` | S→C | 房间列表（名称、成员数、最后消息 id） |
| 0x0025 | `USER_LIST_REQ` | C→S | 请求房间在线成员 |
| 0x0026 | `USER_LIST_ACK` | S→C | 成员列表 |
| 0x0030 | `MSG_SEND` | C→S | 发送消息 |
| 0x0031 | `MSG_SEND_ACK` | S→C | 落盘成功，返回服务端分配的 msg_id |
| 0x0032 | `MSG_RECV` | S→C | 消息下发（广播或历史），**推送** |
| 0x0040 | `HISTORY_REQ` | C→S | 按 `before_id` 向前翻页 |
| 0x0041 | `HISTORY_ACK` | S→C | 历史消息，按 id 升序 |
| 0x0050 | `PING` | 双向 | 心跳（客户端 15s 一次，服务端 45s 无数据则断开） |
| 0x0051 | `PONG` | 双向 | 心跳应答，回填 seq |
| 0x00F0 | `ERROR` | S→C | 错误应答，带错误码与人类可读原因 |
| 0x00F1 | `BYE` | 双向 | 主动关闭前的告别，带原因 |

## 4. payload 编码（TLV）

```
+--------+--------+--------+
| tag 2B | len 4B | value  |
+--------+--------+--------+
```

- 字段顺序**不固定**，按 tag 查找。
- **未知 tag 必须跳过**（因为 len 显式给出）→ 向前兼容。
- 重复 tag：取第一个，其余忽略（防混淆攻击）。
- 所有字符串为 UTF-8 原始字节，不带终止符。
- 定长整数直接以大端二进制放入 value（u8=1B, u16=2B, u32=4B, u64=8B）。
- `array` 类型：value 是 `count u32` + 连续 `[len u32 + TLV blob]`，每个元素本身是一组 TLV。

### 4.1 tag 分配表

| tag | 名称 | 类型 | 用途 |
| --- | --- | --- | --- |
| 0x0001 | `VERSION` | str | 客户端/服务端版本号，如 `0.1.0` |
| 0x0002 | `CLIENT_NAME` | str | `chatt/0.1.0` |
| 0x0003 | `USERNAME` | str | ≤ 32 字节 |
| 0x0004 | `PASSWORD_HASH` | str(64) | `sha256(salt + ":" + password)` 的十六进制 |
| 0x0005 | `SALT` | str(32) | 服务端下发的 16 字节随机盐十六进制 |
| 0x0006 | `ROOM` | str | ≤ 64 字节，仅允许 `[a-zA-Z0-9_.-]` |
| 0x0007 | `TEXT` | str | ≤ 32768 字节（UTF-8） |
| 0x0008 | `CLIENT_MSG_ID` | u64 | 客户端本地自增，用于匹配 ACK |
| 0x0009 | `MSG_ID` | u64 | 服务端分配，房间内单调递增，从 1 开始 |
| 0x000A | `FROM_USER` | str | 发送者用户名 |
| 0x000B | `TS_MS` | u64 | 服务端接收时刻（Unix 毫秒） |
| 0x000C | `CODE` | u16 | 错误码，见 §6 |
| 0x000D | `REASON` | str | 原因描述（UTF-8，≤ 256B） |
| 0x000E | `LIMIT` | u32 | 分页条数，默认 50，上限 200 |
| 0x000F | `BEFORE_ID` | u64 | 拉取 `< before_id` 的消息；0 表示最新 |
| 0x0010 | `MESSAGES` | array | `MSG_RECV` 元素数组 |
| 0x0011 | `USERS` | array | 用户名数组（元素为单字段 TLV） |
| 0x0012 | `ROOMS` | array | 房间信息数组 |
| 0x0013 | `USER_ID` | u64 | 账号唯一 id |
| 0x0014 | `MSG_KIND` | u8 | 0=文本（当前唯一） |
| 0x0015 | `COUNT` | u32 | 房间消息总数（统计用） |
| 0x0016 | `SERVER_TIME` | u64 | 服务端当前毫秒时间 |
| 0x0017 | `SESSION_ID` | u64 | 本次连接标识，便于日志追踪 |
| 0x0018 | `ALLOW_CREATE` | u8 | 1=允许自动建房 |

## 5. 时序

### 5.1 连接与登录

```
C: HELLO{version, client_name}                seq=1
S: HELLO_ACK{version, server_time, session_id} seq=1 (push=0)
C: LOGIN{username, password_hash}             seq=2   ← 若无盐，先返回 SALT
S: LOGIN_ACK{code=0, user_id}                 seq=2
```

未登录状态下，服务端只接受 `HELLO/LOGIN/REGISTER/PING`，其余回
`ERROR(UNAUTHENTICATED)` 但不断连（允许客户端重试登录，3 次失败后断开）。

### 5.2 发消息

```
C: MSG_SEND{room, text, client_msg_id=42}     seq=100
S: MSG_SEND_ACK{msg_id=1007, client_msg_id=42} seq=100
S: MSG_RECV{room, msg_id=1007, from, ts, text} seq=0 push=1   （含发送者自己）
```

发送者自己也通过 `MSG_RECV` 收到消息（保证全序一致），`MSG_SEND_ACK` 只用于确认落盘
与错误重试。客户端收到 ACK 后把本地临时消息标记为已确认，**不重复插入**。

> **ACK 的 seq 固定为 0**：ACK 由存储线程在 fdatasync 完成后异步产生，已脱离原始请求的
> 调用栈，无法回填 seq。客户端一律用 `client_msg_id` 匹配请求。
>
> **ACK 语义**：收到 ACK 表示该消息已经 `fdatasync` 到磁盘（group commit 批量刷盘后才回），
> 因此 `kill -9` 也不会丢。

### 5.3 心跳

客户端每 15s 发 `PING`；服务端 45s 未收到任何帧则断开。服务端每 30s 主动向空闲连接发
`PING`，客户端回 `PONG`。

## 6. 错误码

| 码 | 名称 | 客户端行为 |
| --- | --- | --- |
| 0 | `OK` | — |
| 1 | `BAD_FRAME` | 记录日志，重连 |
| 2 | `BAD_VERSION` | 提示升级客户端，不重连 |
| 3 | `UNAUTHENTICATED` | 触发登录流程 |
| 4 | `BAD_CREDENTIALS` | 提示密码错误，计数 |
| 5 | `USER_EXISTS` | 提示换名 |
| 6 | `ROOM_NOT_FOUND` | 提示房间不存在 |
| 7 | `NOT_A_MEMBER` | 自动 join |
| 8 | `RATE_LIMITED` | 退避 1s 重试 |
| 9 | `PAYLOAD_TOO_LARGE` | 截断提示（不重发） |
| 10 | `TEXT_TOO_LONG` | 提示 |
| 11 | `INTERNAL` | 记录并重连 |
| 12 | `STORAGE_ERROR` | 提示服务端故障，指数退避 |
| 13 | `TIMEOUT` | 重连 |
| 14 | `UNSUPPORTED` | 提示 |

## 7. 兼容性规则

1. 新增字段：分配新 tag，老版本跳过 → 兼容。
2. 修改字段语义：必须提升 `version`，服务端对旧版本回 `BAD_VERSION`。
3. 新增消息类型：接收方遇到未知 type 必须回 `ERROR(UNSUPPORTED)` 且**不断连**。

## 8. 安全边界

- 所有字符串在使用前做长度与字符集校验（房间名白名单、用户名 `[A-Za-z0-9_-]{2,32}`）。
- 文本中的 ANSI 转义序列在客户端渲染前剥离（防止终端注入攻击，见 05 文档）。
- 口令不落明文：`meta.db` 只存 `salt` 与 `sha256(salt + ":" + password)`。
