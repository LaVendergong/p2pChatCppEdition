# 08 编码规范

## 1. 语言与编译

- C++20，`-std=c++20`，不用编译器扩展。
- 全量告警：`-Wall -Wextra -Wshadow -Wconversion -Wno-unused-parameter`，M1 起 `-Werror`。
- Release：`-O2 -DNDEBUG`；Debug：`-O0 -g3 -fsanitize=address,undefined`。
- 不使用 RTTI 以外的高级特性，不用 `std::regex`（性能不可控），不用 `iostream`（除 main 的退出提示）。

## 2. 命名

| 类别 | 风格 | 例子 |
| --- | --- | --- |
| 命名空间 | 小写 | `chat`, `chat::net` |
| 类型/结构体 | PascalCase | `RoomStore`, `FrameHeader` |
| 函数/方法 | snake_case | `append_message()`, `read_before()` |
| 成员变量 | 尾部下划线 | `last_msg_id_` |
| 局部/参数 | snake_case | `payload_len` |
| 常量/枚举值 | 小写 snake 或 kPascalCase | `kMaxFrameSize`, `Err::ok` |
| 宏 | 全大写 + 前缀 | `CHAT_LOG_INFO` |
| 文件名 | snake_case | `io_loop.cpp` |

## 3. 头文件

- 一律 `#pragma once`。
- 公共头放 `include/chat/`，实现私有头放同目录。
- 头文件顺序：对应头 → 标准库 → 项目内。
- 前向声明优先于 include（编译时间）。

## 4. 错误处理

```cpp
// 业务失败用返回值，不抛异常
Result<Message> read_one(int fd, uint64_t offset);

// 必须检查
auto r = store.append(...);
if (!r) { LOG_ERROR("append failed: {}", to_string(r.err())); return r.err(); }
```

- `[[nodiscard]]` 用于所有返回 `Result` 的函数。
- `assert` 只用于"绝不可能"的内部不变量，且不得有副作用。
- 禁止 `catch (...)` 后静默忽略；日志必须带上下文（room/fd/session_id）。

## 5. 资源管理

- fd：`UniqueFd`（move-only，析构 close）。
- 内存：`std::vector/std::string/std::unique_ptr`，禁止裸 `new/delete`。
- 锁：`std::lock_guard` / `std::scoped_lock`，禁止手工 `unlock`（除条件变量）。
- 线程：`std::thread` + `std::atomic<bool>` 停止标志；析构必须 join。

## 6. 并发纪律

1. 服务端：**socket fd 只能由 io 线程读写**。工作线程产出 `std::string` 后投递回 io 线程。
2. 工作线程之间不共享可变状态，除存储引擎（内部加锁）与统计计数器（atomic）。
3. 日志是线程安全的（内部加锁），不在锁内打日志（避免锁序问题）。
4. 禁止在持锁期间调用回调（回调可能重入）。

## 7. 性能纪律

- 热路径避免 `std::string` 隐式分配：用 `std::string_view` 传参。
- 序列化前 `reserve()` 预分配。
- 日志参数用 fmt 风格的轻量格式化，不构造临时大字符串。
- 不在循环里 `shared_ptr` 拷贝（按 `const&` 传）。
- 优先 `emplace_back`，避免二次构造。

## 8. 注释

- 只在"为什么"需要解释时写注释；"做了什么"由代码表达。
- 文件头写模块职责（3 行内）。
- 协议/存储的二进制布局注释必须与文档编号对应，如 `// 见 docs/04 §2`。

## 9. 分层红线

- `common` 不得 include `server/` 或 `client/`。
- `client` 不得 include `server/`。
- 业务层不得直接调用 `write/read`，必须过 `net` 封装（除终端 tty 输出）。
- 任何模块不得依赖"调用顺序正确"这种隐含契约，构造函数完成初始化。

## 10. 提交粒度

一次提交 = 一个模块或一个明确修复；提交信息 `模块: 动词短语`，例如
`storage: 修复尾部截断未同步 room.meta`。
