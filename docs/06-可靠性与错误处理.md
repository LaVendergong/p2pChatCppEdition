# 06 可靠性与错误处理

"精确且稳定"是本次的核心目标，因此单独成文。总原则四句话：

1. **不吞错误**：每个失败都有错误码 + 日志，绝不"返回 0 当作成功"。
2. **不抛异常跨线程**：业务代码用 `Result<T>`，异常只允许在 `main` 边界捕获并转日志。
3. **失败要可见**：ACL 内所有 `[[nodiscard]]`；编译开 `-Wall -Wextra -Werror`。
4. **崩溃可恢复**：任何时刻 `kill -9` 都不能损坏已 ACK 的数据。

## 1. 错误码体系

```cpp
enum class Err : uint16_t {
  ok = 0,
  bad_frame, bad_version, unauthenticated, bad_credentials, user_exists,
  room_not_found, not_a_member, rate_limited, payload_too_large, text_too_long,
  internal, storage_error, timeout, unsupported,
  // 本地（不发给对端）
  sys_errno, eof, would_block
};
```

- 网络层错误附带 `errno`，日志里 `str()` 必带。
- 协议错误码与 `Err` 一一对应（见 03 §6）。

## 2. 输入校验（服务端第一道防线）

| 对象 | 规则 | 违反 |
| --- | --- | --- |
| 帧 magic/version/CRC | 见 03 §1 | 断连 |
| payload_len | ≤ 1 MiB | 断连 |
| username | `[A-Za-z0-9_-]{2,32}` | 拒绝登录 |
| room | `[A-Za-z0-9_.-]{1,64}`，禁止 `..` 与 `/` | 拒绝 |
| text | ≤ 32 KiB，且 UTF-8 合法 | 拒绝 |
| 单连接速率 | ≤ 20 msg/s（令牌桶） | `RATE_LIMITED` |
| 未认证连接 | 只允许 4 种消息，60s 内必须登录 | 断连 |

房间名校验同时防路径穿越（`../../etc`），因为房间名直接用作目录名。

## 3. 超时与心跳

| 计时器 | 默认 | 动作 |
| --- | --- | --- |
| 握手超时 | 10s | 未 HELLO → 断连 |
| 登录超时 | 60s | 未登录 → 断连 |
| 空闲超时 | 45s | 无任何帧 → 先发 PING，再 45s 无响应 → 断连 |
| 发送阻塞 | 30s | 内核发送缓冲久不消化（对端不读） → 断连（防慢速攻击） |
| 客户端重连 | 1s,2s,4s… 上限 30s，带抖动 | 无限重试，状态栏显示倒计时 |

## 4. 客户端重连与补拉

```
断线检测（read 返回 0 / EAGAIN 超时 / 写失败）
  → 状态设为 RECONNECTING，UI 显示 ○
  → 指数退避 + ±20% 抖动
  → 重连成功：HELLO → LOGIN（复用内存中的用户名 + 口令摘要）
  → JOIN 每个之前加入的房间
  → 对每个房间发 HISTORY_REQ(before_id = 本地最大 id)
     客户端按 before_id 语义会拉到"最新的 limit 条"，
     再与本地集合按 id 去重合并
  → 恢复 ONLINE
```

- 所有待发消息在内存队列里保留（上限 1000 条），重连后自动重发；
  重发使用**相同的 client_msg_id**，服务端去重（见 §5）。
- 本地未确认消息在 UI 上标记 `…`，超过 3 次失败标记 `!`。

## 5. 幂等与去重

- 服务端为每个 session 维护 `client_msg_id → msg_id` 的 LRU（最近 1024 条），
  重复的 `client_msg_id` 直接返回原 `msg_id`，不重复落盘。这解决"ACK 丢失后客户端重发"导致
  的重复消息问题。
- 客户端按 `msg_id` 去重（房间内严格单调），历史与实时推送同源。

## 6. 优雅退出

服务端收 `SIGINT/SIGTERM`：

1. 停止 accept，向所有连接发 `BYE{reason="server shutdown"}`。
2. 等待最多 3s 让 socket 发送缓冲清空。
3. flush 所有待写数据 + `fdatasync`，关闭段文件。
4. 打印统计（连接数/消息数/QPS/错误数），退出码 0。

`SIGUSR1` → 打印运行时统计到日志（不退出）。`SIGPIPE` → `SIG_IGN`，
写失败靠返回值判断（否则进程会被对端关闭直接杀掉）。

## 7. 稳定性工程手段

| 手段 | 说明 |
| --- | --- |
| 编译期 | `-Wall -Wextra -Werror -Wshadow -Wconversion`（M1 起），Debug 用 `-fsanitize=address,undefined` |
| 运行期 | 所有 allocation 走 `std::vector/std::string`，无裸 `new` |
| 资源 | fd 用 RAII 包装（`UniqueFd`），无裸 `close` |
| 上限 | 每连接缓冲上限（读 1MB / 写 8MB），房间成员数上限、单帧上限 |
| 日志 | 每 5 分钟打印 RSS/连接数/队列深度，便于发现缓慢泄漏 |
| 浸泡 | `scripts/soak.sh` 跑 72h，采样 RSS 画曲线 |
| 故障注入 | `--fault-inject=truncate-at-N` 在写入第 N 条后截断文件，验证恢复 |

## 8. 已知风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 单 io 线程成为瓶颈 | 高并发下延迟上升 | 压测定位；必要时 M6 改为多 reactor |
| 段文件无限增长 | 磁盘写满 | **已实现** `--max-room-mb N`：超限拒绝写入并回 `storage_error`（不静默删旧数据）。实测 1MB 上限 + 灌 2.4MB，只写入 10591 条，其余被拒 |
| 索引与数据不一致 | 查询错位 | 启动校验 + `--repair` 重建 |
| 时钟回拨 | 时间戳乱序 | 消息排序只依赖 `msg_id`，时间戳仅展示 |
